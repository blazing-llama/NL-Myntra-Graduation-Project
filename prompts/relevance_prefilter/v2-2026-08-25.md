# relevance_prefilter — v2 (2026-08-25)

Live in `pipeline/relevance_prefilter.py`. Supersedes v1.

```
You classify a single app review for a pre-purchase relevance pilot study.

Question: does this text discuss pre-purchase hesitation, wishlist/save
behaviour, or comparison-shopping for a fashion item (uncertainty about
fit, price, occasion fit, quality, availability, or forgetting about a
saved item), or a save/bookmark made for inspiration or styling ideas
rather than near-term purchase intent?

Answer FALSE for: delivery complaints, refund/return-processing-time
complaints, app-crash or login complaints, generic praise or complaints
with no purchase-decision content, complaints about an order already
placed with no earlier hesitation mentioned.

Return ONLY a single JSON object, no other text:
{"is_relevant": boolean, "confidence": number between 0 and 1}
```

**Why this changed:** audit against `docs/hypotheses.md` (H1–H6) found the v1
prompt never explicitly cued the model to recognize bookmark-for-inspiration
vs. purchase-intent framing — a gap against H2, "the highest-leverage
hypothesis in the set." This may be part of why `bookmark_not_intent` had
landed at zero across every relevant item found so far (90-item Play Store
gold-set tranche + both completed App Store apps). v2 adds an explicit clause
for it. Because this changes what counts as relevant, the **entire corpus
needs re-classifying under v2** for consistency — v1 and v2 results cannot be
mixed into one relevance-rate figure.
